Induction & Tree Properties

Key Definition
A perfect binary tree of height h is a tree where all leaves are on the same level and every non-leaf node has exactly two children. A height-0 tree is a single node (1 leaf).

Proof: A Perfect Binary Tree of Height h Has 2h Leaves

Theorem
For a perfect binary tree of height h (where height 0 = single node), the number of leaves is exactly 2h.

Base Case (h = 0)

A tree of height 0 is a single node with no children — it is both the root and a leaf. It has 20 = 1 leaf. ✓

Inductive Hypothesis

Assume a perfect binary tree of height k has exactly 2k leaves.

Inductive Step (show true for h = k + 1)

A perfect binary tree of height k + 1 has a root with two subtrees. Each subtree is a perfect binary tree of height k. By the inductive hypothesis, each subtree has 2k leaves.

All leaves of the full tree come from these two subtrees (the root is not a leaf since k + 1 ≥ 1). Therefore:

Total leaves = 2k + 2k = 2 · 2k = 2k+1

This completes the induction. A perfect binary tree of height h has exactly 2h leaves. □

Useful Corollary

Node Count
A perfect binary tree of height h has 2h+1 − 1 total nodes (sum of all levels: 20 + 21 + … + 2h = 2h+1 − 1 by the geometric series formula).
Practice: How many leaves does a perfect binary tree of height 4 have? How many total nodes?
Solution
Leaves: 24 = 16 leaves
Total nodes: 25 − 1 = 31 nodes
Check: levels 0–4 have 1 + 2 + 4 + 8 + 16 = 31 nodes.
Practice (Fa21 Q1): Prove by induction that the worst case of insertion sort is O(n²) using the fact that it makes at most n(n−1)/2 swaps.
Solution
Base case n = 1: 0 swaps. Formula: 1·0/2 = 0. ✓

Inductive hypothesis: Assume a list of size n requires at most n(n−1)/2 swaps.

Inductive step (n → n+1): A list of size n+1 can have at most n additional swaps (the new element can bubble all the way from position n down to position 0). So:
n(n−1)/2 + n = (n² − n + 2n) / 2 = n(n+1)/2 This equals (n+1)((n+1)−1)/2, confirming the formula holds for n+1. Since the total swaps are O(n²), insertion sort is O(n²) worst case. □

Recurrences & Asymptotic Analysis

Master Theorem
For T(n) = aT(n/b) + f(n) where f(n) is polynomial, compute crit(n) = nlogb(a):
  • Case I: f(n) ∈ O(nlogb(a) − ε) → T(n) ∈ Θ(nlogb(a)) recursion dominates
  • Case II: f(n) ∈ Θ(nlogb(a)) → T(n) ∈ Θ(nlogb(a) log n) tie — multiply by log n
  • Case III: f(n) ∈ Ω(nlogb(a) + ε) → T(n) ∈ Θ(f(n)) function dominates

Interactive Master Theorem Calculator

Enter the parameters of T(n) = a·T(n/b) + Θ(np) to determine the case and solution.

T(n) = Θ(n log n)
Example: T(n) = 4T(n/4) + Θ(n). crit = n^log₄(4) = n¹. f(n) = n¹ = Θ(n¹) → Case II → multiply by log n.

Substitution Method

Use when the Master Theorem does not apply — particularly for recurrences of the form T(n−1) or T(n−k).

T(n) = 3T(n − 1) + 1

Expand by unrolling:

T(n) = 3T(n−1) + 1
     = 3(3T(n−2) + 1) + 1  = 3²T(n−2) + 3 + 1
     = 3²(3T(n−3) + 1) + 3 + 1 = 3³T(n−3) + 3² + 3 + 1
     ...
     = 3ⁿT(0) + 3ⁿ⁻¹ + ... + 3 + 1
     = 3ⁿ · (geometric sum) ≈ 3ⁿ · (3ⁿ−1)/(3−1)
T(n) ∈ Θ(3n)

T(n) = nT(n − 1) + Θ(1)

Unroll the product:

T(n) = n · T(n−1) + 1
     = n(n−1)T(n−2) + n + 1
     = n(n−1)(n−2)T(n−3) + ...
     → T(n) = O(n!)
T(n) ∈ O(n!)

T(n) = T(n/3) + T(n/4) + T(n/5) + n²

Estimation Trick
Since there are 3 recursive calls each on at most n/3, we bound: T(n) ≤ 3T(n/3) + n². Then crit = nlog₃3 = n. Since n² is Ω(n), we are in Case III, so T(n) = Θ(n²).
Practice: Classify T(n) = 2T(n/3) + n√n using the Master Theorem.

crit(n) = nlog₃2 ≈ n0.63.
Since n3/2 ∈ Ω(n0.63 + ε) for ε ≈ 0.87, we are in Case III.
Therefore T(n) = Θ(n√n) = Θ(n^1.5).

Sorting Algorithms

Merge Sort

Recurrence
T(n) = 2T(n/2) + Θ(n)
crit(n) = nlog₂2 = n. Since f(n) = n = Θ(n), this is Case II.
Result: T(n) = Θ(n log n)

Why are all cases the same? Merge Sort always divides the array in exactly half and always merges in Θ(n) time, regardless of the input. There is no "early exit" or pivot-lucky case — every element is always visited at every level of the recursion tree.

QuickSort

Best Case — Θ(n log n)
The pivot always lands in the middle, splitting the array into two equal halves. This gives T(n) = 2T(n/2) + Θ(n) — same as Merge Sort.
Worst Case — Θ(n²)
With a middle-element pivot: an already-sorted or reverse-sorted array causes the middle element to be the min or max, creating a 0/n−1 split each time. T(n) = T(n−1) + Θ(n) → Θ(n²).

Comparison Sort Lower Bound — Ω(n log n)

  • 1There are n! permutations of n distinct elements: n choices for position 1, n−1 for position 2, …, giving n · (n−1) · … · 1 = n!.
  • 2Every permutation must be reachable. If a permutation were missing from the algorithm's decision tree, there would be an input ordering the algorithm cannot correctly sort.
  • 3Decision tree height. A binary decision tree with n! leaf nodes must have height h ≥ log₂(n!). By Stirling's Approximation: n! ≈ √(2πn)(n/e)ⁿ, so log₂(n!) ≈ n log₂(n) − n log₂(e) ≈ Θ(n log n).
  • 4Height = worst case. The height of the decision tree is the longest path = maximum number of comparisons in the worst case.
Key Insight
The height can be more than n log n (a slow sort) but cannot be less than n log n — otherwise there aren't enough leaves for all n! permutations.

Radix Sort (LSD) and Stable Sorting

Radix sort sorts digit-by-digit from the least significant digit (LSD) to the most significant. It runs in O(d · n) where d is the number of digits.

Why O(n) Doesn't Violate Ω(n log n)
The comparison sort lower bound applies only to comparison-based algorithms. Radix sort is not comparison-based — it exploits the structure of the keys (digits), not comparisons between elements. Therefore, the theorem does not apply.

What is a Stable Sort?

A stable sort preserves the relative order of elements with equal keys. If element A appears before element B in the input and they have the same key, A must appear before B in the output.

Why radix sort requires stability: When sorting on digit d, the sort for digit d−1 has already arranged numbers with equal d-digit values. Using an unstable sort on digit d would disrupt that prior ordering, invalidating earlier work.

Practice: Why is MergeSort's best, worst, and average case all Θ(n log n)?
Solution
Merge Sort always divides the problem into exactly two halves of size n/2, regardless of the input data. The merge step always takes Θ(n) time because it must scan all n elements. There is no shortcut path — even a sorted array requires a full merge. Therefore T(n) = 2T(n/2) + Θ(n) always, giving Θ(n log n) in all cases.

Dynamic Programming — LCS

The Longest Common Subsequence (LCS) of two sequences finds the longest subsequence present in both (not necessarily contiguous, but order-preserving). Example: LCS of abacde and abcefa is abce.

Recursive Algorithm (No Memoization)

int lcs(a_seq, b_seq, a_cur=0, b_cur=0):
  if a_cur >= a_seq.length() or b_cur >= b_seq.length():
    return 0
  no_match_a = lcs(a_seq, b_seq, a_cur+1, b_cur)
  no_match_b = lcs(a_seq, b_seq, a_cur, b_cur+1)
  if a_seq[a_cur] == b_seq[b_cur]:
    match = 1 + lcs(a_seq, b_seq, a_cur+1, b_cur+1)
  else:
    match = lcs(a_seq, b_seq, a_cur+1, b_cur+1)
  return max(match, no_match_a, no_match_b)
Runtime Without Memoization
Each call makes 3 recursive calls. The depth is at most m + n (where m = |a_seq|, n = |b_seq|). This gives O(3m+n) — exponential time.
Runtime With Memoization
Each unique (a_cur, b_cur) pair is computed once. There are m × n such pairs, each taking O(1). So the total is Θ(mn).

Why Memoize on (a_cur, b_cur)?

a_seq and b_seq are the same across all calls — they never change. Only the indices a_cur and b_cur change. Two calls with the same (a_cur, b_cur) will always return the same result, so we cache on these indices.

Memoization Table
Size of table: a_cur ∈ {0, 1, …, m} and b_cur ∈ {0, 1, …, n}, so the table has (m+1) × (n+1) entries. Each is filled in O(1), giving total runtime Θ(mn).

What values can a_cur and b_cur hold?

a_cur ∈ {0, 1, 2, …, |a_seq|} and b_cur ∈ {0, 1, 2, …, |b_seq|}. They can equal the length of the sequence (the base case check handles this — when they equal the length, we return 0).

Practice: For LCS of two strings of length 5 and 7, what is the size of the memoization table?
Solution
a_cur ∈ {0,…,5} = 6 values. b_cur ∈ {0,…,7} = 8 values.
Table size = 6 × 8 = 48 entries.
Runtime = Θ(5 × 7) = Θ(35) = Θ(mn).

Graph Algorithms

Adjacency Matrix Representations

Unweighted Graph
Entry M[i][j] = 1 if edge (i,j) exists, 0 otherwise. Diagonal is always 0. For undirected graphs, the matrix is symmetric: M[i][j] = M[j][i].
Weighted Graph
Entry M[i][j] = weight of edge (i,j). Use ∞ (not 0) for no edge, since 0 would mean "free" edge. M[i][i] = ∞ (no self-loops, or 0 by convention).

Breadth-First Search (BFS)

BFS explores all nodes at distance d before nodes at distance d+1. Uses a queue (FIFO).

BFS(G, start):
  visited = {start}
  queue = [start]
  while queue is not empty:
    node = queue.dequeue()
    process(node)
    for neighbor in G.adjacency[node] (sorted alphabetically):
      if neighbor not in visited:
        visited.add(neighbor)
        queue.enqueue(neighbor)
Complexity
Time: O(V + E) — each vertex dequeued once, each edge examined once.
Space: O(V) for visited set and queue.

Depth-First Search (DFS)

DFS explores as deep as possible before backtracking. Uses a stack (LIFO), or recursion.

DFS(G, start):
  visited = {}
  stack = [start]
  while stack is not empty:
    node = stack.pop()
    if node not in visited:
      visited.add(node)
      process(node)
      for neighbor in G.adjacency[node] (reverse alphabetical):
        if neighbor not in visited:
          stack.push(neighbor)
Exam Tip
BFS uses adjacency lists sorted alphabetically. DFS uses adjacency lists sorted in reverse alphabetical order (because the last-pushed neighbor is first-popped). Always check what order the exam specifies!

Modified BFS for k-Friends Problem

To find common degree-k friends of vertices v1 and v2:

  • 1Run BFS from v1, recording the distance from v1 to every node. Call this dist1[].
  • 2Run BFS from v2, recording the distance from v2 to every node. Call this dist2[].
  • 3Scan all nodes. Report node n if dist1[n] ≤ k AND dist2[n] ≤ k.

Total time: O(V + E) for BFS twice + Θ(V) for scan = O(V + E).

Dijkstra's Algorithm

Finds shortest paths from a single source in graphs with non-negative weights.

Dijkstra(G, source):
  dist[source] = 0; dist[v] = ∞ for all other v
  pred[v] = null for all v
  priority_queue Q = all vertices with dist as priority
  while Q is not empty:
    u = Q.extract_min()
    for each neighbor v of u:
      alt = dist[u] + weight(u, v)
      if alt < dist[v]:
        dist[v] = alt
        pred[v] = u
        Q.decrease_key(v, alt)
Complexity
With a binary heap: O((V + E) log V).
With Fibonacci heap: O(E + V log V).
Limitation: Does NOT work with negative-weight edges.

Bellman-Ford & Negative Cycles

Bellman-Ford relaxes all edges |V|−1 times. Unlike Dijkstra, it handles negative-weight edges. However, it cannot handle negative-weight cycles.

Negative Cycle Problem (Sp25 Q10)
In a graph with a negative cycle (e.g., a→b→c→a with total weight −20 + 5 + 8 − 4 = negative), each traversal of the cycle reduces the path cost. Bellman-Ford will keep relaxing edges forever, producing ever-smaller (−∞) values. Detection: if any edge can still be relaxed after |V|−1 iterations, a negative cycle exists.
Edge sequence: a→b, c→d, c→a, d→c, b→c
Iter 1: dist[b]=5, dist[c]=−20+5=−15, dist[a]=−15+5=−10, dist[c] updated again...
Iter 2: dist values continue to decrease indefinitely
→ The cycle b→c→d→c has negative total weight: this causes the problem

Kruskal's Algorithm — Minimum Spanning Tree

Finds the MST by greedily adding the lowest-weight edge that doesn't create a cycle.

  • 1Sort all edges by weight (ascending).
  • 2Initialize a disjoint-set (union-find) structure with one set per vertex.
  • 3For each edge (u, v) in sorted order: if u and v are in different sets, add the edge to the MST and union the two sets.
  • 4Stop when MST has V−1 edges.
Complexity
O(E log E) for sorting + O(E α(V)) for union-find operations ≈ O(E log E).
Practice: Why does Dijkstra fail on negative-weight edges?
Solution
Dijkstra assumes that once a node is extracted from the priority queue (with minimum known distance), its distance is final. With negative edges, a later path through a negative edge could produce a shorter distance to an already-finalized node — violating the algorithm's greedy assumption. This can lead to incorrect shortest paths.

NP-Completeness & Problem Complexity

P
Problems solvable in polynomial time. Examples: sorting, shortest path, MST.
NP
Problems whose solutions can be verified in polynomial time. P ⊆ NP. Whether P = NP is unknown.
NP-Complete
A problem is NP-Complete if it is in NP and every problem in NP can be reduced to it in polynomial time. If any NP-Complete problem is in P, then P = NP.

SAT (Satisfiability)

Given a boolean formula φ(x₁, x₂, …, xₙ) using ∧, ∨, ¬, does there exist an assignment of True/False values that makes φ evaluate to True?

SAT ∈ NP — Verification Algorithm
Certificate: A truth assignment (T/F for each variable).
Verifier: Substitute values into φ and evaluate — takes O(n²) in the worst case (linear scan per clause). This is polynomial, so SAT ∈ NP.
SAT ∈ NP-Complete, but SAT ∉ P... maybe
Even though we can verify SAT in polynomial time, we cannot (as far as we know) find a satisfying assignment in polynomial time in general. SAT is NP-Complete means it's among the hardest in NP. But NP-Complete ≠ not in P — if SAT were in P, then P = NP, which hasn't been proven or disproven.

TSP(k) — Traveling Salesman Problem Restriction

TSP asks for the minimum cost Hamiltonian cycle (visits every vertex exactly once and returns). TSP(k) restricts this: is there such a path with cost exactly k?

TSP(k) ∈ NP — Verification
What a solution looks like: An ordered list of all vertices (a permutation), plus the total cost.

Pseudo-code verifier: 
verify_TSP_k(G, proposed_path, k):
  if proposed_path.size() != |V|: return False
  if any vertex appears more than once: return False
  total = 0
  for i in 0 to |V|−1:
    u = proposed_path[i]
    v = proposed_path[(i+1) % |V|]
    if (u,v) not in E: return False
    total += weight(u, v)
  return total == k
This runs in O(V) — polynomial. So TSP(k) ∈ NP. □
Practice: Explain the difference between NP and NP-Complete.
Solution
NP: Problems where a proposed solution can be verified in polynomial time. This is a broad class — P is a subset of NP.

NP-Complete: Problems that are (1) in NP, AND (2) are at least as hard as every other problem in NP (via polynomial reductions). They are the "hardest" problems in NP. If you could solve any NP-Complete problem in polynomial time, you could solve ALL NP problems in polynomial time (P = NP).

Algorithm Design

Minimum Range Subarray of Size k

Problem: Given a list A = [a₁, …, aₙ], find a subarray B of exactly k elements from A such that max(B) − min(B) is minimized.

Key Insight
If we sort A first, consecutive elements are closest together. The optimal k elements will always be consecutive in the sorted array — any non-consecutive selection can be improved by swapping the outlier for the element that is closer in value.

Example

A = [1, 2, 7, 12, 15, 16], k = 3
Sorted: [1, 2, 7, 12, 15, 16]
Windows: {1,2,7}→6, {2,7,12}→10, {7,12,15}→8, {12,15,16}→4 → Best: {12,15,16}, range=4

Pseudocode

min_range_subarray(A, k):
  // Step 1: Sort A
  sorted_A = sort(A)   // O(n log n)

  // Step 2: Slide a window of size k
  best_range = ∞
  best_start = 0
  for i = 0 to n−k:
    current_range = sorted_A[i+k−1] − sorted_A[i]
    if current_range < best_range:
      best_range = current_range
      best_start = i

  // Step 3: Return the best window
  return sorted_A[best_start .. best_start+k−1]
Time Complexity
Sort: O(n log n)
Window scan: O(n − k) = O(n)
Total: O(n log n)
Space Complexity
O(n) for the sorted copy, O(1) extra for the sliding window scan.
Practice: Trace the algorithm on A = [3, 1, 9, 2, 8, 5] with k = 2.
Solution
Sorted: [1, 2, 3, 5, 8, 9]
Windows of size 2: {1,2}→1, {2,3}→1, {3,5}→2, {5,8}→3, {8,9}→1
Multiple windows tie at range=1. Return any one: e.g. B = {1, 2} or {2, 3} or {8, 9}. All have max − min = 1.
